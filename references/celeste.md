# 《蔚蓝》游戏配置

处理 *Celeste*／《蔚蓝》录像时使用本配置。

## 素材特征

- 重复尝试如果没有压缩或进度变化，容易显得单调。
- 失败、重开、险些成功、通过房间、死亡次数、耗时和路线改进，是主要的可观察叙事信号。
- 精确移动很重要。保留足够的操作前摇，让观众看懂路线为何失败或成功。
- 干净的成功过程依赖此前失败形成反差，不要无故把最终成功切得过碎。
- 高难房间、C 面和金草莓等内容同时具有“表演证据”属性；决定性成功段的连续性会影响可信度，不只是节奏偏好。

## 寻找高价值时刻

标记：

- 第一次能解释障碍机制的失败；
- 具有明显规律的重复失败；
- 不寻常或视觉上荒诞的死亡；
- 路线、时机或推进距离的改善；
- 假胜利以及安全点前的死亡；
- 突破性的输入方式或路线变化；
- 最终成功及其直接余波；
- 进入更难房间、适合作为结尾反转的时刻。

压缩没有新增信息的重复尝试。只有当某次尝试能升级笑点、表现进步、建立回收梗或增强胜利回报时才保留。

## 保护挑战证据

- 最终成功段从关键输入前开始保留，连续展示到房间结束、爱心、结算或其他明确完成反馈；中途切走会让观众无法判断操作是否连续。
- 必须压缩长成功段时，优先裁掉不影响连续证据的过场或另选较短呈现；变速遵循主流程授权，速度变化和时间跳跃必须可见标注，不伪装成连续完成。
- 失败蒙太奇可以高密度包装，决定性尝试则减少遮挡、反应图和无关音效，让路线、角色位置和游戏反馈清楚可辨。
- 需要展示单次高水平操作时，保留进入动作、执行、落点和结果四部分，不只截最华丽的一帧。

## 候选片段与完整成功流程

- 对 `保留`、`备选`、用户新增和局部修改候选，都检查同一房间、目标或技巧是否存在可核验的完整成功流程；这项检查不只针对“高价值片段”。
- 失败、险些成功、荒诞死亡或技巧展示片段，可以关联同一挑战的后续成功过程；不要求完整成功过程与片段候选来自同一次尝试，但必须能解释二者的关系。
- 完整成功流程候选从进入房间或足以解释路线的关键输入前开始，连续保留到房间结束、爱心、结算或其他明确完成反馈。若候选本身已满足该范围，标记为“自身即完整流程”，不要重复导出。
- 配套完整流程作为独立候选保存并与片段候选关联，不默认放入粗剪；它的作用是让用户在需要时可以用连续过程替换节奏版片段。
- 找不到成功过程、素材尚未覆盖或时间码不能核验时，记录对应状态和原因，不用跳切或拼接制造“完整成功”。

## 解释机制与技巧

- 先用一句话命名目标或技巧，再立即给出对应画面；不要先讲完一整段理论才开始演示。
- 字幕只解释输入、判定条件、失败原因或可迁移要点，避免逐字复述画面。
- 同一技巧需要多例时，按“基础示例 → 常见失败 → 实际关卡应用”递进；画面能说明的内容不再增加长口播。
- 无口播教程可以依靠短字幕和连续演示成立，但字幕不得压住角色、刺、落点和移动路径。
- 展示整关或 C 面完成时，开头先给关卡身份，结尾保留爱心或完成反馈；这两个锚点比额外片尾包装更重要。

## 无口播处理

优先使用简短的情境文字：

- 尝试次数和死亡计数；
- 逐渐变得荒诞的中性标签；
- “路线验证”“稳定复现”等伪技术表达；
- 画面难以理解时的简短目标提示。

避免长篇第一人称独白、过早塑造人设，以及仅仅重复画面内容的字幕。

## 默认叙事结构

选择一种：

1. **失败阶梯：** 可理解的失败 → 规律重复 → 更糟变体 → 险些成功 → 干净通关。
2. **虚假掌握：** 早期自信 → 立即打脸 → 反复“证明” → 真正突破 → 克制收尾。
3. **实验报告：** 明确目标 → 预测次数 → 数据不断恶化 → 出现异常 → 验证成功。
4. **单房挑战：** 说明一个限制 → 压缩尝试 → 展示进步 → 保留最终完整过程。

除非素材能够证明，否则不要暗示高水平操作、速通纪录或不存在的挑战规则。
