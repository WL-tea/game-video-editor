# Premiere XML 交接配置

用户选择 Premiere 作为粗剪审片或细剪交接目标时使用本配置。它描述可导入 PR 的源素材对齐时间线，不生成 `.prproj`，也不把 XML 当作最终成片。

## 适用范围

- 使用可直接导入 Premiere 的标准 FCP7 XML；不要把 `.fcpxml` 或任意自定义 XML 声称为可直接导入格式。
- 每个源视频独立生成一条序列和一个 XML，不把多个源文件拼成一条源时间线。
- 只保证恒定帧率、时间码可核验、源文件可读取的素材。VFR、损坏或无法核验的源文件只交付问题记录。
- XML 直接引用原视频的现有路径，保存源文件、源入点、源出点和时间线位置；不复制、转码、移动或修改原素材。
- XML 生成失败、目标软件不可用或用户明确需要独立媒体文件时，才使用 FFmpeg 备用路径，并披露原因。

## 交付物

每个源视频生成：

```text
<源素材ID>__粗剪-vN.xml
<源素材ID>__时间线清单-vN.csv
<源素材ID>__PR导入说明-vN.md
```

生成器入口为 `scripts/premiere_xml.py`。输入 JSON 至少包含 `source_id`、`path`、`duration_frames`、`timebase`、`width`、`height` 和 `candidates`；候选包含 `candidate_id`、`source_start`、`source_end`、`status`，可选 `label`、`candidate_type` 和 `full_flow_id`。使用：

```text
python scripts/premiere_xml.py --input timeline-job.json --output-dir drafts/
```

局部修改或重新生成时用 `--version v2`、`--version v3` 等递增版本，不覆盖旧交付物。

`时间线清单` 是候选映射的权威补充，至少记录：序列 ID、源素材 ID、源文件路径、候选 ID、候选类型、选中状态、源入点、源出点、序列入点、序列出点、视频轨、音频轨、中文标签、完整流程关联 ID、标记文本、生成版本和生成状态。

## 时间线结构

每条序列保持源视频的原始位置和时长，不按粗剪叙事顺序重排：

- `V1/A1`：未选片段，包括不与已选片段重叠的 `备选`；片段按候选边界切开并保持音画链接。
- `V2/A2`：用户确认采用的片段，以及明确选择的完整流程候选。
- `V3/A3` 及后续：与已选片段重叠的完整备选候选。使用最少轨道分层：不重叠的备选复用同一层，只有发生重叠时才增加下一层。
- 重叠备选保持自己的完整源入点和源出点，不因适应轨道而拆碎；它可以与 `V2/A2` 同时覆盖同一序列时间段。
- 所有视频片段与对应音频保持链接；删除、移动或替换时不得静默造成音画失步。
- `保留` 候选彼此重叠时停止生成并要求先解决取舍，不静默叠放或覆盖。

轨道名和片段名使用简体中文，例如 `原视频_未选`、`已选_粗剪`、`备选_重叠层1`，以及 `[备选] S08｜房间3_关键操作`。稳定 ID、源时间码和清单字段保持语言无关。

## 标记与追溯

- 片段名称必须包含候选状态、候选 ID 和中文短标签，名称随片段移动；XML 标记和清单额外记录候选类型、完整源时间段、完整流程关联 ID 和生成版本。
- 推荐或舍弃理由由上游决策表记录；生成器不臆造理由。
- 清单必须重复保存上述信息；如果某个 PR 版本没有保留 XML 中的标记细节，清单仍是权威记录。
- 源时间线的切点可以附加序列标记，用于核对原始边界；用户移动片段后，片段名称和清单仍用于追溯。

## 生成与验证

1. 读取源文件元数据，确认恒定帧率、时间基、时长、音轨和可读取状态。
2. 合并候选、完整流程和用户修改产生的边界，建立不重叠的基础切片；保留候选原始范围和关联关系。
3. 按上面的轨道规则写入源素材引用、入点、出点、序列位置、音频链接、轨道名和标记。
4. 检查同一轨道没有未授权重叠、所有片段均能回到源素材、序列时长没有无法解释的变化，且清单与 XML 一致。
5. 有条件时在目标 PR 版本导入 XML，检查素材链接、轨道布局、首尾边界、音画同步和标记；无法操作 PR 时交付导入步骤，不声称已经导入验证。

粗剪审片使用 PR 序列，不以 MP4 播放作为默认完成条件。用户确认后可以继续使用同一序列进入细剪；用户直接修改 PR 后，只有收到更新的 XML、清单或明确反馈，AI 才更新映射。
