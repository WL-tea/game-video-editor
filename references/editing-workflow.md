需要从游戏录像开始审片、选材、制定方案、执行粗剪、处理修改或验收成片时使用本工作流。它是完整剪辑任务的唯一主流程；游戏、风格和工具配置只补充其中的具体判断与执行方式。

## 协作边界

AI 默认承担观察、整理、建议、机械执行和记录，用户承担审美取舍与最终决定。本次实际进入的阶段使用以下确认点：

1. **候选素材确认：** 用户可以补选被遗漏或低估的片段，也可以删除 AI 高估的片段。
2. **剪辑方向确认：** 用户确认开场、叙事骨架、节奏、风格和结尾处理。
3. **粗剪确认：** 用户依据可追溯的成片映射检查取舍、前摇、余波和局部节奏。
4. **最终成品确认：** 用户查看并接受内容与包装后，草稿才能称为最终成片。

每个确认点记录为 `待确认`、`已确认`、`已授权不等待` 或 `不适用`。用户可预先授权前三个节点不等待，但仍须生成对应记录；最终验收不能预先推定。未进入的阶段标记为 `不适用`，不是“跳过”。

对已确认、可逆且不改变方向的机械操作连续执行，不逐刀询问。用户可回到前一阶段；保留版本和原始时间码以支持回退。

## 阶段一：建立任务

确认或合理推断：游戏、平台、受众与目标情绪；比例、时长和完成度；可用音轨、摄像头、字幕与音乐；游戏和风格配置；用户控制项、AI 授权范围，以及本轮属于流程实验、公开投稿还是局部修改。

只有缺失信息会实质改变结果时才提问，否则写明假设并继续。输出简短任务摘要，不把未经确认的创作偏好伪装成用户决定。

完成条件：素材位置、输出位置、目标和本轮协作范围明确。

## 阶段二：检查并覆盖素材

### 技术检查

保留原始文件。工具允许时，记录文件名、时长、分辨率、帧率、编码、音轨、响度异常、损坏和明显版权风险。需要代理文件时写入独立目录，不覆盖原素材。

### 内容检查

按可核验的时间范围观看素材，并持续更新覆盖表：

| 素材文件 | 起始时间码 | 结束时间码 | 状态 | 备注 |
|---|---|---|---|---|

状态使用 `已检查`、`抽样检查`、`未检查` 或 `无法读取`。没有完整检查时，明确列出空白范围，不用“已看完”概括抽样结果。

将值得记录的事件写入事件日志：

| 事件 ID | 素材时间段 | 类型 | 内容 | 所需上下文 | 技术质量 | 潜在用途 | 置信度 |
|---|---|---|---|---|---|---|---|

事件类型可包括目标、铺垫、普通失败、重复模式、升级、荒诞变体、险些成功、突破、成功和余波。先记录事实，再提出风格化用途；不要因当前方案暂时用不到就省略明显精彩片段。

完成条件：技术问题已报告；检查范围可见；所有已发现的高价值事件都有原素材时间码。

## 阶段三：提交候选素材

将事件分为 `保留`、`备选` 和 `暂不采用`，并输出：

| 候选 ID | 事件 ID | 状态 | 候选类型 | 源素材 ID／文件 | 素材时间段 | 候选文件 | 关联完整流程候选 ID | 完整流程状态 | 叙事功能 | 推荐或舍弃理由 | 建议余量 | 置信度 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|

`候选类型` 使用 `片段候选` 或 `完整流程候选`；`完整流程状态` 使用 `已生成`、`自身即完整流程`、`无对应完整流程`、`待检查` 或 `无法核验`。完整流程候选不是额外的风格创意，而是保证候选可以连贯使用的后备素材。

同时提供：

- 当前最强片段及其判断依据；
- 可能被低估但值得用户亲自查看的边界片段；
- 看似精彩但缺少上下文、技术质量不足或与主线重复的片段；
- 尚未检查或无法判断的素材范围。

### 候选片段导出与命名

实际访问录像并完成筛选时，默认导出 `保留` 候选和需用户判断的边界 `备选`；用户明确要求仅分析、仅表格或不生成媒体文件时可以不导出，并披露这一点。无法访问或导出素材时只能交付时间码表，不得声称已交付候选。

不要重命名、移动或覆盖原始录像。为每个源文件分配稳定的源素材 ID，并在 `selects.csv` 中保存它与原文件名或完整路径的对应关系。候选文件名使用：

```text
S<候选编号>__<源素材ID>__<起始时间码>_<结束时间码>__<短标签>.<扩展名>
```

- 时间码使用 Windows 兼容的 `HH-MM-SS-mmm`；短标签只供浏览，完整说明写入 `selects.csv`。
- 稳定候选 ID、源素材 ID 和时间码保持语言无关；短标签按用户当前语言习惯生成。当前项目默认使用简体中文，例如 `房间3_关键操作`、`房间3_完整成功流程`，不要默认写成 `highlight`、`full_success` 等无法一眼辨认的英文标签。用户明确要求其他语言时服从用户要求。
- `selects.csv` 至少记录 `候选类型`、`关联完整流程候选 ID`、`完整流程状态`、`命名语言` 和未生成或无法核验的原因。语言变化不改变候选 ID、时间码或映射关系；已经确认并被外部引用的文件不因语言变化批量重命名。
- 同一区间的新裁切增加版本号，不覆盖旧版；快速关键帧裁切须记录边界偏差，帧级边界使用可核验的精确方式。
- 导出后抽查首尾、音画同步和时长，确保前摇与余波没有误删。

### 候选片段的完整流程配套检查

对所有可能进入剪辑的 `保留`、`备选`、用户新增候选和局部修改候选执行本检查；`暂不采用` 只有重新进入候选集合后才检查。这里的“覆盖”表示必须记录检查结果，不表示完整流程自动进入粗剪。

1. 若片段候选本身已经从关键输入或进入动作连续展示到房间结束、爱心、结算或其他明确完成反馈，标记 `自身即完整流程`，不重复导出。
2. 否则，在同一房间、目标或技巧的已检查素材中寻找对应成功过程。失败、险些成功或笑点片段可以关联同一挑战的后续成功过程，不要求与片段候选来自同一次尝试。
3. 找到成功过程时，单独导出 `完整流程候选`，从足以解释路线的进入动作或关键输入前开始，连续保留到明确完成反馈，并在 `selects.csv` 中关联一个或多个片段候选。相同成功过程可被多个片段候选复用。
4. 没有对应成功过程、覆盖不足或时间码无法核验时，分别标记 `无对应完整流程`、`待检查` 或 `无法核验`，不得通过跳切、变速或拼接伪造完整成功。
5. 完整流程过长时，只裁掉不影响挑战证据的过场；任何时间跳跃、定格、重复或速度变化都按主流程记录并披露。完整流程候选是否进入粗剪，仍由用户在候选确认或剪辑方向确认时决定。

### 确认点一：候选素材

等待用户补选、删除、提升或降低候选优先级。用户可以直接指定候选 ID，也可以提供新的源素材时间段；新增候选沿用同一导出、命名和完整流程配套检查规则。记录用户的判断，不覆盖事件日志中的原始观察。用户明确授权 AI 自行选材时，可以继续，但仍保留候选和舍弃理由供后续复核。

完成条件：用于方案设计的素材集合已确认，或者已记录用户授予的自主选材范围；所有进入候选集合且可能被使用的片段都有完整流程状态、关联候选 ID 或明确未生成原因。

### 候选确认后的交付模式

用户已经表达选择时不重复提问；否则记录以下一种模式：

| 模式 | 终点与交付 |
|---|---|
| 仅候选包 | 阶段三：候选副本、`selects.csv`、映射和建议 |
| 仅方案交接 | 阶段四：再交付剪辑决策表，不生成媒体草稿 |
| AI 粗剪后用户精剪（默认） | 阶段六：再交付可观看草稿、成片映射和审片建议 |
| AI 完整精剪 | 阶段七：按已确认方案完成可执行包装并等待最终验收 |
| 局部精剪 | 只处理指定候选或成片区间，交付局部预览与边界状态 |

另记录计划版本为 `当前已确认方案` 或 `用户修改方案`，精剪范围为 `全片` 或具体候选／区间。修改影响上游决定时，重新打开相应确认点。模式变化不得破坏已有候选、日志和映射。

## 阶段四：确认剪辑方向

基于已确认候选提出一个主方案；存在实质性取舍时再提供一至两个简短备选。每个方案说明：

- 开场或悬念、观众目标、片段顺序、叙事结构和结尾；
- 节奏变化及字幕、音频和视觉效果密度；
- 是否允许改变播放速度，以及获准变速的具体区间和用途；
- 粗剪需要审片标记、正式字幕草案、二者兼有，还是都不需要；
- 预计时长、主要风险和待决定问题。

不要在用户确认内容方向前投入大量装饰效果，也不要用密集包装掩盖故事骨架问题。

### 确认点二：剪辑方向

等待用户确认主方案或指定修改。把确认结果写入剪辑决策表，而不是只保留在对话中。

完成条件：开场、主体顺序、风格强度和结尾方向已确认。

### 工具与执行边界

- FFmpeg 用于可复现的裁切、拼接、缩放、定格、短重复、响度、简单字幕、音效和预览；
- Premiere、剪映等非线性编辑器用于复杂动画、跟踪、蒙版和依赖人工手感的节奏；
- 无法操作目标软件时，交付精确到时间码的素材、轨道、参数和步骤，不声称已完成。

## 阶段五：建立并执行粗剪

建立按预计成片顺序排列的剪辑决策表：

| 顺序 | 事件 ID | 原素材时间段 | 操作 | 目的 | 画面处理 | 音频／字幕 | 状态 | 置信度 |
|---|---|---|---|---|---|---|---|---|

粗剪用于验证选材、顺序、边界、叙事和节奏；低成本公式化效果可以作为可替换占位。精剪是在粗剪通过后固化已批准的字幕、素材、效果时机、混音、动画和调色。同一种效果所处阶段由目的和确认状态决定，不由效果名称决定。

### 粗剪速度约束

- `1.0x` 指每段连续运动素材保持原始画面与音频节奏。“粗剪”“快节奏”“压缩重复”或风格名称都不构成变速授权；优先通过取舍和裁切缩短。
- 变速授权必须记录候选 ID 或源时间段、倍率和用途。裁切、定格、重复和转场不是变速，但须作为独立操作写入决策表和映射；挑战证据段的时间跳跃必须显式披露。
- 转码、帧率和时间基处理不得意外改变时长。导出后按连续源片段核对时长，排除已记录的定格、重复、转场和容器舍入；无法解释的偏差必须重新生成。

### 粗剪审片标记

粗剪文字分为：

1. **审片标记：** 说明片段来源、候选状态、剪辑理由、可能的梗、遗漏风险、包装建议或待确认问题。它们必须可删除或替换。
2. **正式字幕草案：** 面向观众的对白、情境吐槽、计数器或标题；须经确认，并与审片层使用不同文件或轨道。

审片标记优先交付为 `review-notes-vN.csv`、外挂 `review-captions-vN.srt` 或独立字幕轨。烧录时标注 `审片版`，并保留无标记草稿或可复现的干净导出方式。用户决定保留某条建议时，将其清理并复制到正式字幕层，不直接沿用审片轨。

详细建议表记录成片时间码、原素材时间码、类型、说明和建议动作；画面只放标记 ID 或短提示，不遮挡关键操作。

粗剪后生成成片映射：

| 成片时间段 | 事件 ID | 原素材时间段 | 当前操作 | 与方案差异 | 备注 |
|---|---|---|---|---|---|

完整播放草稿，检查黑帧、断音、错误片段、跳切、字幕占位和时长。额外核对是否存在未授权变速，以及审片标记是否保持可删除。不要仅根据命令成功就声称粗剪可用。

完成条件：草稿能够完整播放；每个成片片段可追溯；与确认方案的偏差已列明。

## 阶段六：审核和局部修改

### 确认点三：粗剪

向用户同时交付草稿、成片映射和以下摘要：

- 已用与未用候选、舍弃理由，以及前摇或余波调整；
- 占位效果、AI 已完成项、人工任务和待确认项；
- 获准的变速、定格或重复；没有变速时明确写 `连续运动素材均为 1.0x`；
- 审片标记与正式字幕草案的关闭方式，以及最需要判断的三至五处内容。

按成片时间码记录反馈：

| 意见 ID | 版本 | 成片时间段 | 问题 | 期望结果 | 约束 | 优先级 | 状态 |
|---|---|---|---|---|---|---|---|

处理小片段修改时：

1. 确认使用成片还是原素材时间码，并记录须保留的音乐、字幕和相邻镜头；
2. 只修改受影响的决策和映射；
3. 先输出带前后文的局部预览，认可后再合入完整版本；
4. 将意见标记为 `已处理`、`保留现状` 或 `待确认`，不静默忽略。

如果局部修改产生了新的片段候选，或改用另一个源素材时间段，必须重新执行候选片段的完整流程配套检查；如果只是修改已有片段的字幕、音效或包装，则沿用原候选关联，并在映射中记录未改变源素材范围。

若反馈改变整体叙事方向，退回阶段四；若只是候选片段取舍变化，退回阶段三或五。不要在局部修改中未经说明重构整条视频。

完成条件：阻塞性的内容意见已处理，剩余意见及其状态透明。

## 阶段七：包装、导出和验收

内容粗剪通过后，先由用户决定保留、替换或删除审片标记，再完成正式字幕、音乐、音效、缩放、动画、调色和响度等包装。

自动执行已确认的公式化包装。独特笑点、跨素材联想和复杂视觉概念先列为创意提案，注明作用、素材、成本与替代方案；未经确认不合入。

精剪前建立 `asset-plan-vN.csv`，记录成片时间码、类型、用途、来源或路径、授权、工具、状态和替代方案。状态使用 `已提供`、`已批准使用`、`占位` 或 `待用户补充`；来源或权限不明的第三方素材只能作为占位。

仅 `AI 完整精剪` 和相应的 `局部精剪` 范围进入本阶段；局部模式不得改变未授权区间，并在映射中标记边界和状态。

应用游戏与风格配置，同时检查：

- 开头是否明确呈现事件、问题或结果悬念；
- 目标、空间关系、失败原因和最终成功是否容易理解；
- 重复是否被压缩、升级或形成回收；
- 字幕是否可读，关键游戏声或对话是否清楚；
- 包装是否放大真实事件而没有遮挡关键操作；
- 画面比例、安全区域、编码和输出路径是否正确。

完整导出前先检查高风险短预览。导出后从头到尾播放候选成片，并列出 AI 已完成、仍需人工处理和等待用户决定的项目。

### 确认点四：最终成品

等待用户查看并验收内容与包装。该确认不能预先授权；未经接受，文件名和说明使用 `draft` 或 `candidate`。发布或其他外部写入另需明确授权。

完成条件：技术检查通过，未决事项已披露，用户已经验收或明确接手剩余精修。

## 阶段八：实验复盘

普通项目记录素材／成片时长、工时、用户改选、修改轮数和主要误判。风格对照实验另按 [style-experiment.md](style-experiment.md) 记录指标与迭代结论。一次实验只产生暂定结论；仅把重复验证的规律写回配置或自动化脚本。

## 停止与回退条件

- 没有清晰目标、有效变化或可用结尾时，停止强行成片，返回候选素材或请求其他素材。
- 时间码无法核验、素材存在损坏或检查范围不足时，不生成看似精确的完整粗剪。
- 方向未确认或粗剪未通过时，不投入高成本包装；局部意见改变整体逻辑时回退到相应阶段。
- 草稿无法完整播放、片段不可追溯，或最终导出仍有未披露的占位和人工任务时，不进入下一确认点。
