# 人机协作剪辑工作流

需要从游戏录像开始审片、选材、制定方案、执行粗剪、处理修改或验收成片时使用本工作流。它是完整剪辑任务的唯一主流程；游戏、风格和工具配置只补充其中的具体判断与执行方式。

## 协作边界

默认让 AI 承担观察、整理、建议、机械执行和记录，让用户承担审美取舍与最终决定。除非用户明确授权连续越过某个节点，否则设置四个确认点：

1. **候选素材确认：** 用户可以补选被遗漏或低估的片段，也可以删除 AI 高估的片段。
2. **剪辑方向确认：** 用户确认开场、叙事骨架、节奏、风格和结尾处理。
3. **粗剪确认：** 用户依据可追溯的成片映射检查取舍、前摇、余波和局部节奏。
4. **最终成品确认：** 用户验收内容和包装后，草稿才能被称为最终成片。

对已经确认、可逆且不改变创作方向的机械操作连续执行。不要为每次裁切、转码或文件命名逐项询问。用户随时可以要求回到前一阶段；保留历史版本和原始时间码以支持回退。

## 项目产物

使用等价结构保存产物；用户已有项目结构时服从现有结构，不强制搬迁：

```text
project/
├─ source/                     # 原始素材，只读
├─ analysis/
│  ├─ media-report.md          # 技术检查
│  ├─ coverage-map.csv         # 素材检查覆盖范围
│  ├─ event-log.csv            # 全部值得记录的事件
│  ├─ selects.csv              # 保留、备选、暂不采用
│  └─ edit-decisions.csv       # 已确认的剪辑决策
├─ drafts/
│  ├─ draft-v1.mp4
│  └─ edit-map-v1.csv          # 成片与原素材映射
├─ previews/                   # 局部修改预览
├─ exports/                    # 待用户验收或已验收版本
└─ review/
   ├─ review-v1.md
   └─ experiment-log.md
```

不复制或提交原始录像、音频、缓存和导出视频到技能仓库。剪辑项目产物应放在用户指定的素材工作区。

## 阶段一：建立任务

确认或合理推断：

- 游戏、平台、观众预期和目标情绪；
- 画面比例、目标时长和期望完成度；
- 可用的游戏声、口播、队伍语音、摄像头、字幕和音乐；
- 本次采用的游戏配置与风格配置；
- 用户希望亲自控制的部分，以及授权 AI 连续执行的范围；
- 本轮是内部流程实验、公开投稿还是已有成片的局部修改。

只有缺失信息会实质改变结果时才提问，否则写明假设并继续。输出简短任务摘要，不把未经确认的创作偏好伪装成用户决定。

完成条件：素材位置、输出位置、目标和本轮协作范围明确。

## 阶段二：检查并覆盖素材

### 技术检查

保留原始文件。工具允许时，记录文件名、时长、分辨率、帧率、编码、音轨、响度异常、损坏和明显版权风险。需要代理文件时写入独立目录，不覆盖原素材。

### 内容检查

按可核验的时间范围观看素材，并持续更新覆盖表：

| 素材文件 | 起始时间码 | 结束时间码 | 状态 | 备注 |
|---|---|---|---|---|

状态使用 `已检查`、`抽样检查`、`未检查` 或 `无法读取`。没有完整检查时，明确列出空白范围，不用“已看完”概括抽样结果。

将值得记录的事件写入事件日志：

| 事件 ID | 素材时间段 | 类型 | 内容 | 所需上下文 | 技术质量 | 潜在用途 | 置信度 |
|---|---|---|---|---|---|---|---|

事件类型可包括目标、铺垫、普通失败、重复模式、升级、荒诞变体、险些成功、突破、成功和余波。先记录事实，再提出风格化用途；不要因当前方案暂时用不到就省略明显精彩片段。

完成条件：技术问题已报告；检查范围可见；所有已发现的高价值事件都有原素材时间码。

## 阶段三：提交候选素材

将事件分为 `保留`、`备选` 和 `暂不采用`，并输出：

| 事件 ID | 状态 | 素材时间段 | 叙事功能 | 推荐理由或舍弃理由 | 建议前后余量 | 置信度 |
|---|---|---|---|---|---|---|

同时提供：

- 当前最强片段及其判断依据；
- 可能被低估但值得用户亲自查看的边界片段；
- 看似精彩但缺少上下文、技术质量不足或与主线重复的片段；
- 尚未检查或无法判断的素材范围。

### 确认点一：候选素材

等待用户补选、删除、提升或降低候选优先级。记录用户的判断，不覆盖事件日志中的原始观察。用户明确授权 AI 自行选材时，可以继续，但仍保留候选和舍弃理由供后续复核。

完成条件：用于方案设计的素材集合已确认，或者已记录用户授予的自主选材范围。

## 阶段四：确认剪辑方向

基于已确认候选提出一个主方案；存在实质性取舍时再提供一至两个简短备选。每个方案说明：

- 开场事件或悬念；
- 观众需要理解的目标；
- 片段顺序与叙事结构；
- 节奏如何变化；
- 字幕、音频和视觉效果的密度；
- 胜利、失败或反高潮的处理；
- 预计时长；
- 方案的主要风险与仍待决定的问题。

不要在用户确认内容方向前投入大量装饰效果，也不要用密集包装掩盖故事骨架问题。

### 确认点二：剪辑方向

等待用户确认主方案或指定修改。把确认结果写入剪辑决策表，而不是只保留在对话中。

完成条件：开场、主体顺序、风格强度和结尾方向已确认。

## 阶段五：建立并执行粗剪

建立按预计成片顺序排列的剪辑决策表：

| 顺序 | 事件 ID | 原素材时间段 | 操作 | 目的 | 画面处理 | 音频／字幕 | 状态 | 置信度 |
|---|---|---|---|---|---|---|---|---|

把内容取舍与装饰效果分开。优先完成能够检验故事是否成立的粗剪；复杂字幕、动画、跟踪、蒙版和高成本包装可先使用占位说明。

根据任务选择执行方式：

- FFmpeg 适合可复现的裁切、拼接、缩放、响度处理、简单字幕和预览导出；
- Premiere、剪映等非线性剪辑软件适合复杂包装和需要人工手感的节奏调整；
- 无法直接操作目标软件时，输出带原素材时间码、顺序和效果说明的可执行交接清单。

粗剪后生成成片映射：

| 成片时间段 | 事件 ID | 原素材时间段 | 当前操作 | 与方案差异 | 备注 |
|---|---|---|---|---|---|

完整播放草稿，检查黑帧、断音、错误片段、跳切、字幕占位和时长。不要仅根据命令成功就声称粗剪可用。

完成条件：草稿能够完整播放；每个成片片段可追溯；与确认方案的偏差已列明。

## 阶段六：审核和局部修改

### 确认点三：粗剪

向用户同时交付草稿、成片映射和以下摘要：

- 使用了哪些候选素材；
- 哪些已确认候选最终没有使用以及原因；
- 哪些地方缩短了前摇或余波；
- 哪些效果仍是占位；
- 最需要用户判断的三至五处内容。

按成片时间码记录反馈：

| 意见 ID | 版本 | 成片时间段 | 问题 | 期望结果 | 约束 | 优先级 | 状态 |
|---|---|---|---|---|---|---|---|

处理小片段修改时：

1. 确认反馈针对成片时间码还是原素材时间码；
2. 记录需要保留的音乐落点、字幕、相邻镜头或其他约束；
3. 只修改受影响的决策和映射；
4. 优先输出带少量前后文的局部预览；
5. 用户认可后再合入下一完整版本；
6. 将意见标记为 `已处理`、`保留现状` 或 `待确认`，不静默忽略。

若反馈改变整体叙事方向，退回阶段四；若只是候选片段取舍变化，退回阶段三或五。不要在局部修改中未经说明重构整条视频。

完成条件：阻塞性的内容意见已处理，剩余意见及其状态透明。

## 阶段七：包装、导出和验收

内容粗剪通过后再完成字幕、音乐、音效、缩放、动画、调色和响度等包装。应用游戏与风格配置，同时检查：

- 开头是否明确呈现事件、问题或结果悬念；
- 目标、空间关系、失败原因和最终成功是否容易理解；
- 重复是否被压缩、升级或形成回收；
- 字幕是否可读，关键游戏声或对话是否清楚；
- 包装是否放大真实事件而没有遮挡关键操作；
- 画面比例、安全区域、编码和输出路径是否正确。

完整导出前先检查高风险短预览。导出后从头到尾播放候选成片，并列出 AI 已完成、仍需人工处理和等待用户决定的项目。

### 确认点四：最终成品

等待用户验收内容与包装。未经用户验收，文件命名和说明使用 `draft` 或 `candidate`；用户明确接受后才能标记为最终成片。

完成条件：技术检查通过，未决事项已披露，用户已经验收或明确接手剩余精修。

## 阶段八：实验复盘

记录：

- 素材时长、成片时长和各阶段制作工时；
- AI 判断被用户补选、删除或调整的片段；
- 粗剪和局部修改的轮数；
- 本轮最耗时或最容易误判的环节；
- 投稿后可获得的留存、互动和定性反馈；
- 下一轮只改变的一至两个变量；
- 哪些规律已经重复验证，值得写回游戏、风格或工具配置。

一次实验只产生暂定结论。没有经过重复测试的操作不要固化为自动化脚本。

## 停止与回退条件

- 没有清晰目标、有效变化或可用结尾时，停止强行成片，返回候选素材或请求其他素材。
- 时间码无法核验、素材存在损坏或检查范围不足时，不生成看似精确的完整粗剪。
- 用户尚未确认叙事方向时，不投入高成本包装。
- 草稿无法完整播放或成片片段无法追溯时，不进入粗剪确认。
- 局部意见改变整体逻辑时，回退到方向确认，不把结构性问题伪装成小修。
- 最终导出存在未检查范围、占位内容或未披露的人工任务时，不声称已经完成。
